Key resilience properties con fi rmed in source: ZSET member encoding is   f"{timestamp_score}:{time.time_ns()}"   — the nanosecond su ffi x guarantees member uniqueness even when two events land in the same wall-clock second, which a plain timestamp-as-member scheme would silently collide/overwrite. Self-trimming window: every write both adds the new member (   zadd   ) and evicts everything older than the window (   zremrangebyscore(key,   0,   window_start)   ) in the same call — the ZSET never grows unbounded. TTL safety net:   self.redis.expire(key,   window_sec   +   60)   — even if a metric stops receiving events entirely, its ZSET key self-destructs   window_sec   +   60  seconds after the last write, so dead metrics don't leak Redis memory inde fi nitely. Live demotion, not just startup gating:   _redis_available   is   fl ipped to   False  inside the exception handler of both   update_metric_window   and  get_window_count   , not only in   _init_redis   . This means a Redis instance that dies mid-session (after a successful startup ping) still triggers fallback on the very next operation, without waiting for a restart. Symmetric SQLite fallback:   metric_windows   is a literal SQLite table (   metric_id   ,  event_timestamp   ) that mirrors the ZSET's data model — insert-then-prune on write, range-count on read — so alert evaluation produces the same semantic result (count of events within   window_sec   ) regardless of which backend is active. The same live-demotion pattern is applied to   get_last_processed_id   /  save_last_processed_id   (Redis key   alert_engine:last_processed_id   , in- memory   self._last_processed_id   as the fallback) so the event-polling cursor survives a Redis outage without reprocessing or dropping events. Correction against reference context: the reference material characterizes this as simply "independent Redis fallback for sliding-window metric tracking via ZSETs," implying Redis-or-nothing. Source shows a third state the reference omits: SQLite is a fully symmetric, permanent fallback backend (via the   metric_windows   table), not a placeholder — alert evaluation continues functioning inde fi nitely on SQLite alone if Redis never recovers, with no feature loss beyond raw throughput. sqlglot.transpile(sql)   is used purely as a syntax/parseability check.
